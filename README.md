# 安全版 Codex 额度悬浮窗

这是一个面向 Windows 10/11 的本地悬浮小组件，用于显示 Codex 主额度和账户方案；当 Codex app-server 提供套餐标识时，可显示 `Free`、`Go`、`Plus`、`Pro 5×` 与 `Pro 20×`，缺失时显示“未知”。

它不是从第三方项目复制或打包出来的程序。项目使用 Windows 自带的 .NET Framework 和 WPF，从本目录源码在你的电脑上编译，不需要 npm、Electron、安装器或网络下载。

![展开界面预览](preview.png)

> 该版本使用 WPF，只能在 Windows 10/11 上运行；macOS 需要单独实现原生界面，不能直接运行这里生成的 EXE。

> 这是社区维护的非官方工具，与 OpenAI 无隶属或背书关系；“Codex”和相关名称归其各自权利人所有。

## 先用起来

1. 右键 `Build.ps1`，选择“使用 PowerShell 运行”；也可以在本目录执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
   ```

2. 双击 `Start-CodexQuotaWidget.cmd`。

3. 小组件默认以 `100 × 100` 的额度悬浮球出现在屏幕右上角并保持置顶：鼠标经过会亮起彩色光晕、扩散一圈波纹并提亮额度环，圆环文字始终保持原始像素尺寸；短按球体展开完整面板；按住不动约 220 毫秒可开始拖动，或者按下后移动超过系统点击抖动范围便立即开始拖动，松开都不会误触展开。完整面板中的“−”会平滑收回成球，“×”会完全结束程序。

界面使用 WPF 逐像素透明圆角、高 DPI 渲染、深蓝/青绿/紫色渐变和紧凑卡片布局；可见悬浮球为 `100 × 100`，Spark 卡片隐藏时展开面板约为 `324 × 142`。“账户方案”和底部更新时间之间只保留紧凑间距，方案名称在卡片右侧区域居中，左上角标题与额度状态也重新排版。展开时额度圆球固定在原来的屏幕坐标，外框只在它周围铺开，文字和卡片随后淡入滑入；收回时内容先退场，外壳一边柔化一边收回圆球后方。圆角与高度使用同一时间轴，避免中途出现一帧小方块。

为避免 Windows 在调整原生窗口尺寸时产生跳帧，程序运行期间始终保持一个透明的 `556 × 202` 宿主窗口，不再在动画首尾移动或缩放它；可见面板仍只有约 `324 × 142`，多余透明区域会通过 Windows 命中测试直接穿透，不会挡住下面窗口的鼠标操作。拖动范围按可见圆球而不是透明宿主计算：拖动时每 16 毫秒直接读取系统鼠标位置，并用逐帧位移更新窗口，触边后反向也会立即跟随，不会积累阻尼或在长按生效时重置位置；球在宿主中使用唯一固定锚点，位于工作区右半边时面板向左展开，位于左半边时向右展开。切换方向只改变面板的延伸方向，不再搬动球或补偿宿主坐标，因此拖过屏幕中线松手时圆心也不会闪跳。

程序内嵌专属多尺寸图标：深色圆角底、青蓝额度环、绿色状态灯和白色闪电标记。任务栏、窗口切换器和 EXE 文件会使用同一图标。

- 展开界面固定隐藏 Spark 专属额度，不占用卡片空间；底层解析仍保留，手动运行 `Probe.ps1` 时可以用于诊断。如果服务端以后提供普通 Codex 的真实第二额度窗口，它仍可正常显示。
- 独立模型额度不会参与悬浮球百分比计算；悬浮球始终只代表 Codex 主额度，避免混淆。
- “账户方案”按当前 Codex 套餐标识显示：`free` → `Free`、`go` → `Go`、`plus` → `Plus`、`prolite` → `Pro 5×`、`pro` → `Pro 20×`。未知标识保留安全回退；套餐和倍率只根据服务端标识映射，不会根据剩余百分比猜测。
- 主色跟随主额度剩余量分档：`50%–100%` 为青绿/蓝色，`20%–49%` 为金色/橙色，低于 `20%` 为红色/粉色；圆环、外框、状态灯、卡片描边和深色背景会用约 `360 ms` 的过渡同步换色。
- 展开后短按面板空白、信息卡片或额度圆环会收回悬浮球；右上角按钮和底部错误详情不参与该手势。移动超过 `4 DIP` 或按住达到 `220 ms` 才进入拖动，拖动松手不会误收起。展开态只有鼠标位于额度圆环上时才提亮描边、卡片轮廓并扫过一层轻微渐变高光；移出圆环立即恢复静态，不缩放或模糊文字。
- 自动刷新首次失败后会再尝试 3 次，间隔依次为 1、1.5、2 秒；重试期间保留上一次成功额度，全部失败后才显示 `--%`。每轮读取完成后重新计时 60 秒，手动刷新不会再紧接着撞上旧的自动刷新时刻。

`bin\OpenCodexWithQuota.exe` 是组合启动器：它先打开额度窗，再通过已注册的 `codex://` 协议打开 Codex。它不驻留后台，也不修改系统设置。

## 可选：创建组合启动快捷方式

构建后可以给 `bin\OpenCodexWithQuota.exe` 手动创建桌面快捷方式。通过这个快捷方式启动时，它会先打开额度悬浮窗，再通过系统已注册的 `codex://` 协议打开 Codex。

项目不会自动修改现有 Codex 快捷方式，也不会创建后台监控器、计划任务或开机启动项。从开始菜单、任务栏或其他入口直接打开 Codex 时，额度窗不会自动启动。

如果只想验证额度读取而不打开界面：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Probe.ps1
```

## 安全边界

以下边界针对构建后的主程序 `bin\SafeCodexQuotaWidget.exe` 在运行期间；构建、图标生成、测试和可选组合启动器属于单独的开发/启动工具。

- 不读取 `%USERPROFILE%\.codex\auth.json` 或任何 Token、Cookie、浏览器数据。
- 不包含 HTTP、Socket、WebView 或遥测代码。小组件本身不能向任意网站上传数据。
- 不写注册表、不创建计划任务、不开机自启、不安装服务、不写日志。
- 不调用 PowerShell、`cmd.exe` 或其他 shell。
- 唯一启动的子进程是 `codex.exe app-server --listen stdio://`。
- 启动前使用 Windows `WinVerifyTrust` 验证文件签名，并要求签名证书主题包含 `OpenAI`。
- 仅接受 OpenAI Codex 的受限安装目录：`%LOCALAPPDATA%\OpenAI\Codex\bin` 或 `%ProgramFiles%\WindowsApps\OpenAI.Codex_*`。
- 每次读取结束后立即关闭 Codex 子进程；60 秒后才会再次读取。

Codex 子进程本身可能按其正常工作方式联系 OpenAI 服务来获取额度。小组件只接收额度字段，不会把返回结果写入磁盘。

## 为什么仍会显示“未知发布者”

本地生成的 `SafeCodexQuotaWidget.exe` 没有商业代码签名证书。它的可信依据不是“发布者”提示，而是：可读源码、零第三方依赖、在你自己的电脑上从源码编译。`Build.ps1` 会输出生成文件的 SHA-256。

## 文件说明

- `src\SafeCodexQuotaWidget.cs`：安全额度读取、签名校验和旧界面参考实现。
- `src\SafeCodexQuotaWidgetWpf.cs`：当前使用的 WPF 界面和程序入口。
- `assets\SafeCodexQuotaWidget.ico`：包含 16–256 像素尺寸的程序图标。
- `tools\GenerateIcon.cs`：无需第三方图片库的可复现图标生成器。
- `Build.ps1`：调用 Windows 自带的 `csc.exe` 编译，不下载依赖；同时生成界面程序和控制台探测程序。
- `Probe.ps1`：无界面读取一次额度，用于验证。
- `Start-CodexQuotaWidget.cmd`：双击启动已经编译好的程序。
- `tests\CaptureTransitionFrames.cs`：逐帧录制展开/收起动画，用于检查圆角闪帧和位置跳动。
- `tests\QuotaParserTests.cs`：验证主额度、第二窗口、独立模型额度的选择规则，以及 Free、Go、Plus、Pro 5×/20× 的显示映射。
- `tests\RetryPolicyTests.cs`：验证成功、恢复、耗尽、永久错误和关闭取消时的自动重试行为。
- `tests\PointerGestureTests.cs`：验证短按展开/收起、轻微抖动、位移拖动、长按边界和拖动松手互不混淆。
